## 真实 AI 与 Demo 的边界

- 在线临时演示和 `docs/demo.html` 使用**预置故事**，不是实时 AI。
- 已在本机实际调用配置的供应商，完成 `lantern` → `envelope` 两章连续生成。最终一轮两章 HTTP 200、`source: ai`，本地接口耗时分别 **7.959 秒、13.646 秒**；第二章带入第一章上下文。
- 最终两章目标词和词表校验通过；一般过去时、人物移动及钥匙归属有所改善。
- 仍有 “empty hall” 与桌子描述的歧义，以及 “opened a wooden desk” 的不自然搭配。不能据此宣称自然语言质量已完全通过。
- 提示词优化最多两轮，合计四次真实上游请求（包含一次既有自动重试）。模拟供应商测试不计入真实调用。本次 GitHub 发布未重新调用供应商。
- 没有公开提供真实 AI 密钥；缺少配置时 AI 模式返回明确错误，不偷偷回退成 Demo。

## 当前限制

1. 仅 A2、悬疑故事、十个目标词；初始熟词表是产品假设，尚未进行用户词汇水平测量。
2. 进度保存在当前浏览器；没有账号、数据库和跨设备同步。多标签页可能相互覆盖进度，建议单标签使用。
3. 没有针对 StoryWords 开展学习效果研究，不能声称提升长期记忆或给出学习提升百分比。
4. 临时公网隧道依赖演示电脑持续运行；仓库中的源码与离线 Demo 可独立获取。
5. 公网和离线 Demo 保留之前验收的界面；仓库源码包含后来完成的午夜蓝界面，界面外观可能不同。

## 研究依据

- [CHI 2024 / Putting Things into Context](https://www.media.mit.edu/publications/putting-things-into-context/)：272 名参与者的研究支持个性化内容与学习动机的关系，研究没有发现学习表现的显著提升；不能转换成 StoryWords 的记忆效果承诺。
- [EMNLP 2025 / SRS-Stories](https://aclanthology.org/2025.emnlp-industry.44/)：支持词汇约束故事生成的技术可行性及质量讨论；生成质量评价不等同于长期记忆或学习效果验证。

自动测试和浏览器检查证明的是软件行为与可运行性，真实 AI 调用证明的是接口与有限样例能够生成；两者都不能替代教育效果研究。
